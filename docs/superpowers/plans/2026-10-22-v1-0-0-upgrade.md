# v1.0.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native; the box forbids parallel subagents). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the red CI into a green, release-ready v1.0.0 branch with coverage, secret scanning and a refreshed README.

**Architecture:** One `.ruby-version` file becomes the single source of truth for the Ruby toolchain; the Gemfile, GitHub Actions, the Dockerfile and Dependabot all read it. CI gains a coverage artifact and a gitleaks job. Docs are refreshed around the existing demo media.

**Tech Stack:** Ruby 3.4.11, Rails 7.2, Bundler 2.6, RSpec + Minitest, SimpleCov, RuboCop, bundler-audit, gitleaks, GitHub Actions.

**Spec:** the frozen task's Definition of Done (items 1-4); root cause recorded in `HANDOFF.md`.

## Global Constraints

- Ruby `3.4.11` everywhere (`.ruby-version`, `Gemfile ruby file:`, `setup-ruby`, `Dockerfile FROM ruby:3.4.11-slim`).
- Lockfile `PLATFORMS` must include `x86_64-linux` (CI/Docker) and keep `x64-mingw-ucrt` (author's Windows box).
- CHANGELOG heading exactly `## [1.0.0] - 2026-10-21` (superseded 2026-10-22: the coordinator renamed the release to `[1.4.0] - 2026-10-22` because `v1.0.0` already existed).
- No URLs/hosts/tokens from the local environment in the repo. Push only via `push.sh`.

## Review Focus

1. Dependabot resolving against a newer Ruby than CI -> toolchain consistency spec fails if any consumer drifts from `.ruby-version`.
2. Bundler-audit advisories introduced by the lockfile refresh -> audit job must pass with justified ignores only.
3. Ruby 3.4 default->bundled gem moves (base64, bigdecimal, csv, drb, mutex_m) -> full suite + zeitwerk check on 3.4.
4. Coverage artifact missing when tests fail -> upload step uses `if: always()`.
5. gitleaks false positives on dummy CI credentials -> job runs on full history and passes.
